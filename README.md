# 手工造纸帘纹与工序档案

围绕手工造纸的纸帘、纤维料批、抄纸工序与成纸样本建立一体化档案。界面可登记纸帘丝径与帘纹间距、推算网目密度，跟踪料批打浆度，复测抄纸帘纹偏差，并按匀度与帘纹条数复核样本。所有业务数据保存在浏览器 IndexedDB 中，无需后端服务。

## Docker 一键启动

```bash
cp .env.example .env && docker compose up -d --build
```

默认映射端口为 `21807`。启动后访问 `http://localhost:21807`。

## 数据存储说明

数据存储使用 IndexedDB，Dexie 数据库名为 `gbpapermill-db`。

- `version(1)`：建立 `moulds`、`fiberBatches`、`sheetRuns`、`paperSamples` 四张表及编号、日期、状态等索引。
- `version(2)`：为四张表加入 `schemaRev` 索引，并通过 `upgrade` 将存量记录回填为版本 `2`。
- `version(3)`：四张主数据表加入主数据修订版本 `rev` 索引（存量回填为 `1`），新增 `settlements`（生产结算单）与 `settlementTasks`（月末批组任务）两张表。
- 数据库首次创建时通过 `populate` 写入 5 张纸帘、5 个纤维料批、8 槽抄纸工序和 6 个成纸样本。
- 页面顶部的“导出 JSON”可下载六张表的完整备份。

## 月末生产结算说明

月末在“月末结算”页按纸帘合并当月多槽工序，生成生产结算单。

- **封存**：结案时把当时的帘纹间距标准、各料批打浆度、按当时标准算出的每槽偏差、成纸样本条数与匀度整体快照存入结算单，并记录四类主数据的版本指纹（`rev`）。之后主数据如何修改，封存值都不变。
- **失效与待对账**：任一关联主数据（纸帘标准、打浆度、工序实测间距、样本结果）被修订，对应 `rev` 自增，系统复查后将关联结算单置为“待对账”并写明失效来源；页面重新打开时也会复查一遍。
- **重新对账**：对“待对账”单据按当前主数据逐项复算，输出帘纹标准、打浆度、偏差、样本结果四类核对项的封存值/当前值/差异与完成率。全部一致（完成率 100%）时按当前版本重新结案，状态转为“对账一致”；不一致则原结算与封存值照旧保留、留在“待对账”，可继续重试。
- **结案限制**：每槽工序必须有成纸样本、同一张结算单只能含同一纸帘的工序，否则不能结案；月末批量处理逐组校验，不合格批组跳过并把原因持久化到批组任务，页面重开后仍可接着处理（单组重试或整月批量均可）。同月补登的新槽会在补齐样本后形成“补 N”补封单。
- 各台账页提供“修订标准 / 修订打浆度 / 复测结果”入口（纸帘状态变更不影响封存），修改后关联结算立即失效。

## 核心功能与路由表

| 路由 | 页面标题 | 核心功能 |
| --- | --- | --- |
| `/` | 工作台 | 查看纸帘状态分布、本周工序数、待复检样本、待对账结算单与标准工序路径 |
| `/moulds` | 纸帘台帐 | 筛选纸帘，登记新纸帘，实时推算网目密度、登记修补与修订帘纹标准 |
| `/fibers` | 纤维料批台账 | 按原料和打浆度筛选、比较，修订打浆度，展开查看关联抄纸工序 |
| `/runs` | 抄纸工序记录台 | 按日期和帘号筛选，登记工序并即时判断 ±0.2 mm 帘纹偏差 |
| `/samples` | 成纸样本与透光检验卡 | 按匀度与帘纹条数分档，查看透光帘纹预览、归档位置与复测样本结果 |
| `/settlements` | 月末生产结算 | 批量/手工封存结案、查看跳过原因、待对账单据按当前主数据重算差异与完成率 |

未匹配的地址会回到工作台。
